용어를 하나씩 보기 전에 카프카 전체 구조부터 그렸다. 공식 문서 Introduction과 Confluent의 Kafka 101 앞부분을 같이 읽었다.

## 요약

- 카프카에 쓰는 단위는 이벤트(레코드)다. 키, 값, 타임스탬프, 헤더(선택)로 이뤄진다.
- 이벤트는 토픽에 쓰이고, 토픽은 실제로는 여러 파티션으로 나뉜 '추가만 되는 로그'다.
- 프로듀서는 밀어 넣고(push), 컨슈머는 직접 가져간다(pull). 컨슈머가 자기 속도로 읽는다.
- 읽어도 지워지지 않는다. 보존 기간(기본 7일)이 지나거나 크기 제한에 걸려야 지워진다.
- 같은 토픽을 여러 컨슈머 그룹이 각자 처음부터 끝까지 따로 읽을 수 있다.

## 1. 이벤트

공식 문서는 이벤트를 '세상에서 무슨 일이 일어났다는 기록'이라고 설명한다. 예를 들면 이렇다.

| 부분 | 예 |
|---|---|
| 키 | user-1 |
| 값 | 주문 생성 1001 |
| 타임스탬프 | 2025-10-18 14:02:11 |
| 헤더(선택) | trace-id=abc123 |

키는 없어도 되지만, 같은 키의 이벤트를 같은 파티션에 모아 순서를 지키게 하는 데 쓴다. 이건 다음 글에서 직접 확인한다. 카프카 입장에서 키와 값은 그냥 바이트다. 문자열인지 JSON인지는 보내는 쪽과 받는 쪽이 정한다.

## 3. 메시지 큐와 뭐가 다른가

처음엔 RabbitMQ 같은 메시지 큐와 뭐가 다른지 헷갈렸다. 정리해 보니 '읽으면 사라지느냐'가 가장 큰 차이였다.

| 비교 | 전통적인 메시지 큐 | 카프카 |
|---|---|---|
| 읽은 뒤 | 처리 확인(ack)하면 큐에서 사라진다 | 그대로 남는다. 보존 기간이 지나야 지워진다 |
| 여러 소비자 | 보통 한 메시지를 한 소비자가 가져간다 | 그룹마다 따로 처음부터 끝까지 읽는다 |
| 어디까지 읽었나 | 브로커가 메시지별로 관리 | 컨슈머 그룹이 파티션별 오프셋(번호)을 커밋 |
| 다시 읽기 | 어렵다 | 오프셋을 되돌리면 된다 |
| 순서 | 큐 단위 | 파티션 안에서만 보장 |

4.1에는 Queues for Kafka(공유 그룹)가 미리보기로 들어왔다. 파티션을 한 컨슈머가 독점하지 않고 메시지 단위로 나눠 처리하는, 큐에 가까운 방식이다. 아직 미리보기라 기초 공부에서는 일반 컨슈머 그룹만 본다.

## 4. 왜 pull인가

컨슈머가 브로커에 '내가 읽은 다음 것 줘'라고 요청하는 방식이다. 브로커가 밀어주면 느린 컨슈머가 버티지 못하는데, pull이면 각자 처리할 수 있는 만큼만 가져간다. 컨슈머가 멈췄다 돌아와도 자기 오프셋부터 다시 읽으면 된다.

> **쉬운 설명**
>
> 카프카 토픽은 공책이고, 이벤트는 공책에 한 줄씩 적는 일기다. 쓰는 사람(프로듀서)은 맨 아래에 이어서 적기만 한다. 읽는 사람(컨슈머)은 책갈피(오프셋)를 꽂아 두고 자기 속도로 읽는다. 여러 사람이 같은 공책을 각자 다른 책갈피로 읽을 수 있고, 읽었다고 페이지를 찢지 않는다. 공책이 너무 두꺼워지면 오래된 페이지부터 버린다(보존 기간).

## 헷갈렸던 것들

- 토픽은 논리적인 이름이고, 실제로 디스크에 쌓이는 단위는 파티션이다.
- 컨슈머가 읽었다고 데이터가 지워지지 않는다. 지우는 건 보존 정책이다.
- 순서는 토픽 전체가 아니라 파티션 하나 안에서만 보장된다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 이벤트 스트리밍 | 이벤트를 실시간으로 받아 저장하고, 여러 곳에서 계속 읽고 처리하는 방식 |
| 토픽 | 이벤트를 분류하는 이름 |
| 파티션 | 토픽을 나눈 단위. 추가만 되는 로그 파일이다 |
| 오프셋 | 파티션 안에서 이벤트마다 붙는 순서 번호 |
| 보존(retention) | 이벤트를 얼마나 오래, 얼마나 많이 남길지 정하는 정책 |
| 컨슈머 그룹 | 파티션을 나눠 읽는 컨슈머 묶음. 그룹마다 오프셋을 따로 관리한다 |

## 복습 문제

**1.** 같은 토픽을 결제 팀과 분석 팀이 둘 다 처음부터 끝까지 읽어야 한다. 컨슈머 그룹을 어떻게 나눠야 하는가?

**2.** '카프카는 메시지를 읽으면 삭제한다'는 말이 틀린 이유를 설명해라.

**3.** 컨슈머가 2시간 멈췄다가 다시 시작했다. 보존 기간이 7일이라면 그동안 쌓인 이벤트는 어떻게 되는가?

## 답과 풀이

1. 그룹을 둘(예: billing, analytics)로 나눈다. 오프셋은 그룹별로 관리되므로 두 그룹이 서로 영향 없이 전체를 읽는다. 같은 그룹에 넣으면 파티션을 나눠 가져서 각자 일부만 읽게 된다.

2. 카프카는 읽기와 삭제가 따로다. 컨슈머는 어디까지 읽었는지(오프셋)만 기록하고, 데이터는 retention.ms, retention.bytes 같은 보존 정책에 따라 지워진다.

3. 그대로 남아 있다. 컨슈머가 마지막으로 커밋한 오프셋부터 다시 읽어서 밀린 2시간 분을 따라잡는다. 그동안 쌓인 양이 랙(lag)이다.
