1과목 네 번째, 관계. 관계 표기 요소(관계명, 관계차수, 관계선택사양)와 ERD를 보고 관계를 읽는 법을 정리했다.

## 요약

- 관계는 엔터티의 인스턴스 사이에 있는 논리적인 연관성이다.
- 관계는 존재에 의한 관계(부서와 사원)와 행위에 의한 관계(고객과 주문)로 나뉜다.
- 관계는 관계명, 관계차수(1:1, 1:N, M:N), 관계선택사양(필수, 선택)으로 표기한다.
- 관계는 '각 A는 한(여러) B를 항상(때때로) ~한다'처럼 읽는다.

## 1. 관계의 정의와 종류

**관계(Relationship)** 는 엔터티의 인스턴스끼리 맺는 논리적인 연관성이다. '사원은 부서에 소속된다'처럼 동사로 표현된다. 인스턴스 하나하나가 관계로 이어진 것은 **페어링(pairing)** 이라고 한다.

| 종류 | 설명 | 예 |
|---|---|---|
| 존재에 의한 관계 | 한 엔터티가 존재하는 것만으로 다른 엔터티와 연관된다 | 사원은 부서에 소속된다 |
| 행위에 의한 관계 | 어떤 행위가 있어야 관계가 생긴다 | 고객은 주문을 한다 |

UML 클래스 다이어그램에서는 연관 관계(실선)와 의존 관계(점선)를 구분하지만, ERD에서는 존재 관계와 행위 관계를 표기법으로 구분하지 않는다.

## 2. 관계의 표기 요소

| 요소 | 뜻 | 예 |
|---|---|---|
| 관계명(Membership) | 관계의 이름. 양쪽 엔터티 관점에서 각각 짓는다 | '소속된다' / '포함한다' |
| 관계차수(Cardinality) | 한 인스턴스가 상대 엔터티의 인스턴스 몇 개와 관계를 맺는가 | 1:1, 1:N, M:N |
| 관계선택사양(Optionality) | 관계가 반드시 있어야 하는가(필수), 없어도 되는가(선택) | 사원은 반드시 부서에 속한다(필수) |

### 관계차수

| 차수 | 설명 | 예 |
|---|---|---|
| 1:1 | 한 인스턴스가 상대 인스턴스 하나와만 관계를 맺는다 | 사원과 사원 상세 정보 |
| 1:N | 한 인스턴스가 상대 인스턴스 여러 개와 관계를 맺는다 | 부서 하나에 사원 여러 명 |
| M:N | 양쪽 모두 여러 개와 관계를 맺는다. 실제 테이블로 만들 때는 두 개의 1:N 관계로 풀어 관계 엔터티(교차 엔터티)를 둔다 | 학생과 강좌 → 수강 신청 |

### IE 표기법 읽기

IE(까마귀발) 표기법에서 선 끝의 기호는 다음 뜻이다.

| 기호 | 뜻 |
|---|---|
| 막대 ( \| ) | 하나 |
| 까마귀발 ( < ) | 여러 개 |
| 동그라미 ( ○ ) | 선택(없어도 됨, 0개 가능) |
| 막대가 하나 더 | 필수(반드시 있음) |

## 3. 관계 읽기

ERD의 관계는 정해진 순서로 읽는다.

1. 기준 엔터티를 '한(One)' 또는 '각(Each)'으로 읽는다.
2. 대상 엔터티의 관계 참여도(하나, 여러)를 읽는다.
3. 관계선택사양(항상, 때때로)과 관계명을 읽는다.

| 방향 | 읽는 법 |
|---|---|
| 사원 → 부서 | 각 사원은 한 부서에 항상 소속된다 |
| 부서 → 사원 | 각 부서는 여러 사원을 때때로 포함한다 |

필수 관계는 '항상', 선택 관계는 '때때로'로 읽는다.

> **쉬운 설명**
>
> 반과 학생의 관계를 떠올리면 쉽다. '각 학생은 한 반에 항상 속한다', '각 반은 여러 학생을 때때로 포함한다'(새로 만든 반에는 아직 학생이 없을 수 있으니까). 학생과 동아리는 한 학생이 여러 동아리에, 한 동아리에 여러 학생이 있을 수 있어서 M:N이고, '동아리 가입'이라는 표를 따로 만들어 푼다.

## 4. 관계를 정의할 때 확인할 사항

- 두 엔터티 사이에 관심 있는 연관 규칙이 있는가?
- 두 엔터티 사이에 정보의 조합이 발생하는가?
- 업무 기술서나 장표에 관계 연결에 대한 규칙이 적혀 있는가?
- 업무 기술서나 장표에 관계 연결을 가능하게 하는 **동사(Verb)** 가 있는가?

## 헷갈렸던 것들

- 관계 표기 요소는 관계명, 관계차수, 관계선택사양 세 가지다.
- 관계차수는 Cardinality, 관계선택사양은 Optionality이다.
- M:N 관계는 관계 엔터티를 두어 두 개의 1:N 관계로 푼다.
- ERD에서는 존재에 의한 관계와 행위에 의한 관계를 구분해 표기하지 않는다.
- IE 표기법의 동그라미는 선택(0개 가능)을 뜻한다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 관계 | 엔터티 인스턴스 사이의 논리적 연관성 |
| 페어링 | 인스턴스 하나하나가 맺은 관계 |
| 관계차수(카디널리티) | 1:1, 1:N, M:N 같은 참여 개수 |
| 관계선택사양 | 관계가 필수인지 선택인지 |
| 관계 엔터티 | M:N 관계를 풀기 위해 만든 엔터티 |

## 복습 문제

**1.** 관계의 표기 요소가 아닌 것은?

① 관계명 ② 관계식별자 ③ 관계차수 ④ 관계선택사양

**2.** '고객은 주문을 한다'처럼 어떤 행위가 있어야 생기는 관계는?

① 존재에 의한 관계 ② 행위에 의한 관계 ③ 상호배타적 관계 ④ 자기 참조 관계

**3.** 학생과 강좌가 M:N 관계일 때 테이블로 구현하는 방법으로 알맞은 것은?

① 학생 테이블에 강좌번호 컬럼을 여러 개 둔다 ② 수강 신청 같은 관계 엔터티를 만들어 두 개의 1:N 관계로 푼다 ③ 강좌 테이블에 학생번호를 쉼표로 이어 저장한다 ④ 두 테이블을 하나로 합친다

**4.** '각 부서는 여러 사원을 때때로 포함한다'에서 '때때로'가 나타내는 것은?

① 관계차수가 1:1이다 ② 관계가 필수 사항이다 ③ 식별 관계다 ④ 관계가 선택 사항이다

## 답과 풀이

1. ② 관계 표기 요소는 관계명, 관계차수, 관계선택사양이다.
2. ② 행위에 의한 관계다.
3. ② M:N 관계는 관계 엔터티로 푼다.
4. ④ '때때로'는 선택, '항상'은 필수다.
