엔터티에서는 특징 여섯 가지, 유무형과 발생 시점에 따른 분류가 단골이다. 특징 여섯 개는 예시와 묶어서 정리했다.

## 요약

- 엔터티는 업무에 필요하고 유용한 정보를 저장하고 관리하려는 집합적인 것이다.
- 엔터티는 업무에 필요하고, 식별자로 구분되고, 인스턴스가 두 개 이상이고, 업무 프로세스에 쓰이고, 속성이 있고, 다른 엔터티와 관계가 있어야 한다.
- 유무형에 따라 유형, 개념, 사건 엔터티로 나뉜다.
- 발생 시점에 따라 기본(키), 중심, 행위 엔터티로 나뉜다.

## 1. 엔터티의 정의

**엔터티(Entity)** 는 업무에서 관리해야 할 정보를 담는 '집합'이다. 사원, 부서, 주문처럼 명사로 표현되고, 그 안의 개별 대상을 **인스턴스(instance)** 라고 한다. 엔터티는 테이블, 인스턴스는 테이블의 한 행에 해당한다.

## 2. 엔터티의 특징

| 특징 | 설명 | 예외와 예 |
|---|---|---|
| 업무에 필요한 정보 | 해당 업무에서 반드시 필요하고 관리하고자 하는 정보여야 한다 | 병원에서 '환자'는 엔터티지만, 일반 회사에서는 아니다 |
| 식별자로 구분 | 유일한 식별자로 인스턴스를 구분할 수 있어야 한다 | 사원은 사원번호로 구분한다 |
| 인스턴스의 집합 | 영속적으로 존재하는 인스턴스가 두 개 이상 있어야 한다 | 인스턴스가 하나뿐인 '회사 정보'는 엔터티로 보기 어렵다 |
| 업무 프로세스에서 이용 | 업무 프로세스가 엔터티를 이용(생성, 조회, 수정, 삭제)해야 한다 | 쓰이지 않는 엔터티는 잘못 설계된 것일 수 있다 |
| 속성 보유 | 반드시 속성이 있어야 한다 | 주식별자만 있고 일반 속성이 없는 엔터티는 관계 엔터티를 빼면 적절하지 않다 |
| 관계 보유 | 다른 엔터티와 최소 하나 이상의 관계가 있어야 한다 | 통계성 엔터티, 코드성 엔터티, 시스템 처리용 내부 엔터티(로그 등)는 관계를 생략할 수 있다 |

## 3. 엔터티의 분류

### 유무형에 따른 분류

| 분류 | 설명 | 예 |
|---|---|---|
| 유형 엔터티(Tangible Entity) | 물리적인 형태가 있고 안정적이며 지속적으로 활용된다 | 사원, 물품, 강사 |
| 개념 엔터티(Conceptual Entity) | 물리적인 형태는 없지만 관리해야 할 개념적 정보다 | 조직, 보험상품 |
| 사건 엔터티(Event Entity) | 업무를 수행하면서 발생한다. 발생량이 많고 통계 자료로 쓰인다 | 주문, 청구, 미납 |

### 발생 시점에 따른 분류

| 분류 | 설명 | 예 |
|---|---|---|
| 기본 엔터티(키 엔터티, Fundamental) | 다른 엔터티에 의존하지 않고 독립적으로 생성된다. 다른 엔터티의 부모가 되며 자신의 고유한 주식별자를 가진다 | 사원, 부서, 고객, 상품 |
| 중심 엔터티(Main) | 기본 엔터티로부터 발생하고, 업무에서 중심 역할을 한다. 데이터 양이 많고 다른 엔터티와 관계를 통해 많은 행위 엔터티를 만든다 | 계약, 사고, 청구, 주문 |
| 행위 엔터티(Active) | 두 개 이상의 부모 엔터티로부터 발생한다. 내용이 자주 바뀌거나 양이 계속 늘어난다 | 주문 목록, 사원 변경 이력 |

>
> 온라인 쇼핑몰을 떠올리면 쉽다. '고객'과 '상품'은 주문이 없어도 먼저 존재하는 기본 엔터티다. 고객이 물건을 사면 '주문'이라는 중심 엔터티가 생기고, 주문 하나에 상품 여러 개가 담기면서 '주문 상품'이라는 행위 엔터티가 계속 쌓인다.

## 4. 엔터티의 명명 규칙

- 현업에서 실제로 쓰는 용어를 사용한다.
- 약어는 되도록 쓰지 않는다.
- 단수 명사로 쓴다(사원들 X, 사원 O).
- 모든 엔터티에서 이름이 유일해야 한다.
- 엔터티가 생성되는 의미대로 이름을 붙인다(예: '고객제품'보다 '계약').

## 헷갈렸던 것들

- 엔터티는 인스턴스가 **두 개 이상**이어야 한다.
- 통계성, 코드성, 시스템 처리용 엔터티는 관계를 생략할 수 있다.
- 주문, 청구처럼 업무 수행 중에 발생하는 것은 **사건 엔터티**, 보험상품처럼 형태가 없는 개념은 **개념 엔터티**이다.
- 두 개 이상의 부모 엔터티로부터 발생하는 것은 **행위 엔터티**이다.
- 엔터티 이름은 단수 명사로 짓는다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 엔터티 | 업무에서 관리할 정보의 집합 |
| 인스턴스 | 엔터티에 속한 개별 대상 |
| 유형 / 개념 / 사건 엔터티 | 물리적 형태가 있음 / 형태 없는 개념 / 업무 중 발생 |
| 기본 / 중심 / 행위 엔터티 | 독립적으로 생성 / 기본 엔터티에서 발생 / 두 개 이상 부모에서 발생 |

## 복습 문제

**1.** 엔터티의 특징으로 옳지 않은 것은?

① 업무에서 필요한 정보여야 한다 ② 인스턴스가 하나만 있어도 된다 ③ 반드시 속성이 있어야 한다 ④ 유일한 식별자로 구분되어야 한다

**2.** 업무를 수행하면서 발생하는 엔터티로, 발생량이 많고 통계에 쓰이는 것은?

① 유형 엔터티 ② 개념 엔터티 ③ 사건 엔터티 ④ 기본 엔터티

**3.** 다음 중 기본 엔터티에 해당하는 것은?

① 주문 ② 고객 ③ 주문 목록 ④ 사원 변경 이력

**4.** 관계를 생략해도 되는 엔터티가 아닌 것은?

① 통계성 엔터티 ② 코드성 엔터티 ③ 중심 엔터티 ④ 시스템 처리용 로그 엔터티

## 답과 풀이

1. ② 엔터티는 인스턴스가 두 개 이상이어야 한다.
2. ③ 주문, 청구처럼 업무 중에 발생하는 것은 사건 엔터티다.
3. ② 고객은 독립적으로 생성되는 기본 엔터티다. 주문은 중심, ③과 ④는 행위 엔터티다.
4. ③ 중심 엔터티는 다른 엔터티와 관계를 맺어야 한다.
