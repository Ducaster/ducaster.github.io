데이터 모델과 SQL 두 번째, 관계와 조인의 이해. 모델의 관계가 SQL에서 조인으로 어떻게 바뀌는지, 계층형 모델과 상호배타적 관계가 무엇인지 정리했다. 예제는 '실습 환경과 예제 데이터' 편의 EMP, DEPT 테이블.

## 요약

- 정규화로 테이블을 나누면 데이터가 여러 테이블에 흩어지고, 이를 다시 합쳐 보는 방법이 조인이다.
- 조인은 모델의 관계, 즉 부모의 기본키와 자식의 외래키를 연결 고리로 쓴다.
- 한 엔터티가 자기 자신과 관계를 맺는 것을 순환 관계(자기 참조)라고 하고, 계층형 데이터 모델로 표현한다. 조회할 때는 셀프 조인이나 계층형 질의를 쓴다.
- 상호배타적 관계는 자식이 두 부모 가운데 하나와만 관계를 맺는 경우다.

## 1. 관계에서 조인으로

정규화된 모델에서 사원의 부서 이름은 DEPT 테이블에만 있다. '개발부 사원 목록과 부서 이름'을 보려면 두 테이블을 이어야 한다. 이때 연결 고리가 관계를 구현한 **PK-FK** 이다.

{{< mermaid >}}
erDiagram
  DEPT ||--o{ EMP : "DEPT.DEPTNO = EMP.DEPTNO"
  DEPT {
    NUMBER DEPTNO PK
    VARCHAR2 DNAME
  }
  EMP {
    NUMBER EMPNO PK
    VARCHAR2 ENAME
    NUMBER DEPTNO FK
  }
{{< /mermaid >}}

```sql
SELECT E.EMPNO, E.ENAME, E.DEPTNO, D.DNAME
  FROM EMP E
  JOIN DEPT D ON E.DEPTNO = D.DEPTNO
 WHERE E.DEPTNO = 20
 ORDER BY E.EMPNO;
```

| EMPNO | ENAME | DEPTNO | DNAME |
|---|---|---|---|
| 1002 | 이부장 | 20 | 개발부 |
| 1004 | 최과장 | 20 | 개발부 |
| 1005 | 정대리 | 20 | 개발부 |
| 1006 | 강사원 | 20 | 개발부 |

같은 값을 가진 행끼리 잇는 이 방식을 **등가 조인(EQUI JOIN)** 이라고 한다. 조인의 종류와 문법은 SQL 기본의 '조인', '표준 조인' 편에서 자세히 다룬다.

> **쉬운 설명**
>
> 정규화는 학생 명부와 반 정보를 두 장의 종이로 나누는 일이고, 조인은 '반 번호'를 보고 두 종이를 나란히 맞대는 일이다. 반 번호가 같은 줄끼리 이어 붙이면 '학생 이름 + 담임 이름'을 한 줄로 볼 수 있다.

## 2. 계층형 데이터 모델과 셀프 조인

사원과 관리자처럼 같은 엔터티 안에서 인스턴스끼리 상하 관계가 있는 것을 **순환 관계(Recursive Relationship, 자기 참조 관계)** 라고 한다. 이 관계를 가진 모델을 **계층형 데이터 모델**이라고 한다.

{{< mermaid >}}
erDiagram
  EMP |o--o{ EMP : "MGR = EMPNO (관리한다)"
  EMP {
    NUMBER EMPNO PK "사원번호"
    VARCHAR2 ENAME "사원명"
    NUMBER MGR FK "관리자 사원번호"
  }
{{< /mermaid >}}

EMP의 MGR은 같은 EMP 테이블의 EMPNO를 가리킨다. 사원과 그 관리자를 한 줄로 보려면 EMP를 두 번 써서 자기 자신과 조인하는 **셀프 조인(Self Join)** 을 한다. 같은 테이블을 두 번 쓰므로 반드시 별칭(E, M)으로 구분한다.

```sql
SELECT E.ENAME AS 사원, M.ENAME AS 관리자
  FROM EMP E
  JOIN EMP M ON E.MGR = M.EMPNO
 WHERE E.DEPTNO = 30
 ORDER BY E.EMPNO;
```

| 사원 | 관리자 |
|---|---|
| 박부장 | 김대표 |
| 조과장 | 박부장 |
| 윤대리 | 박부장 |
| 장사원 | 박부장 |

여러 단계의 상하 관계를 한 번에 펼쳐 보려면 Oracle의 `START WITH ... CONNECT BY` 같은 **계층형 질의**를 쓴다. SQL 활용의 '계층형 질의와 셀프 조인' 편에서 다룬다.

## 3. 상호배타적 관계

**상호배타적 관계(Exclusive OR Relationship)** 는 자식 엔터티가 여러 부모 엔터티 가운데 **하나와만** 관계를 맺는 경우다. 예를 들어 주문은 개인 고객이 하거나 법인 고객이 하고, 둘이 동시에 하지는 않는다.

{{< mermaid >}}
erDiagram
  PERSONAL_CUSTOMER |o--o{ ORDERS : "주문한다(개인)"
  CORPORATE_CUSTOMER |o--o{ ORDERS : "주문한다(법인)"
  ORDERS {
    NUMBER ORDER_NO PK
    VARCHAR2 CUST_TYPE "개인 P / 법인 C"
    VARCHAR2 CUST_NO FK
  }
{{< /mermaid >}}

이런 관계는 주문 테이블에 '고객 구분' 컬럼을 두고, 그 값에 따라 개인 고객 테이블이나 법인 고객 테이블과 조인한다. ERD에서는 두 관계선을 아치(호)로 묶어 '둘 중 하나'임을 표시한다.

## 헷갈렸던 것들

- 조인의 연결 고리는 모델의 관계를 구현한 PK와 FK이다.
- 순환 관계(자기 참조)는 같은 엔터티 안의 인스턴스끼리 맺는 관계이고, 셀프 조인이나 계층형 질의로 조회한다.
- 셀프 조인은 같은 테이블을 두 번 쓰므로 **별칭**이 반드시 필요하다.
- 상호배타적 관계는 여러 부모 가운데 하나와만 관계를 맺는다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 조인 | 여러 테이블의 데이터를 관계를 근거로 합쳐 보는 것 |
| 등가 조인 | 같은 값을 가진 행끼리 잇는 조인 |
| 순환 관계 | 같은 엔터티 안에서 맺는 관계(자기 참조) |
| 계층형 데이터 모델 | 순환 관계로 상하 구조를 표현한 모델 |
| 셀프 조인 | 같은 테이블을 자기 자신과 조인하는 것 |
| 상호배타적 관계 | 여러 부모 중 하나와만 관계를 맺는 관계 |

## 복습 문제

**1.** 같은 테이블 안에서 사원과 그 관리자를 한 줄로 조회하는 방법은?

① 카티션 곱 ② 집합 연산 ③ 서브쿼리만 사용 ④ 셀프 조인

**2.** 셀프 조인에 대한 설명으로 옳지 않은 것은?

① 반드시 서로 다른 두 테이블이 있어야 한다 ② 같은 테이블을 두 번 이상 사용한다 ③ 테이블 별칭을 써서 구분한다 ④ 순환 관계를 조회할 때 쓴다

**3.** 주문이 개인 고객 또는 법인 고객 가운데 하나와만 관계를 맺는 관계는?

① 순환 관계 ② 식별 관계 ③ M:N 관계 ④ 상호배타적 관계

## 답과 풀이

1. ④ 셀프 조인이다.
2. ① 셀프 조인은 한 테이블을 별칭으로 나눠 쓴다.
3. ④ 상호배타적 관계다.
