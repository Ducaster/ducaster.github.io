관계 표기(필수, 선택)가 '같이 처리되어야 하는 작업 묶음'을 어떻게 드러내는지가 요점이다.

## 요약

- 트랜잭션은 더 이상 나눌 수 없는 논리적인 작업 단위로, 모두 성공하거나 모두 실패해야 한다.
- 데이터 모델에서 두 엔터티가 반드시 함께 생겨야 한다면, 그 관계를 양쪽 모두 **필수(Mandatory)** 로 표현한다.
- 필수 관계로 묶인 엔터티의 데이터는 한 트랜잭션 안에서 함께 입력하고 함께 COMMIT한다.
- 트랜잭션은 원자성, 일관성, 고립성, 지속성(ACID)을 가진다.

## 1. 트랜잭션이란

**트랜잭션(Transaction)** 은 하나의 업무를 처리하기 위해 함께 실행되어야 하는 작업의 묶음이다. 계좌 이체가 대표적인 예다.

{{< mermaid >}}

  S["이체 시작"] --> A["A 계좌에서 10만 원 출금"]
  A --> B["B 계좌에 10만 원 입금"]
  B --> C{"둘 다 성공?"}
  C -->|"예"| CM["COMMIT<br>변경 확정"]
  C -->|"아니오"| RB["ROLLBACK<br>모두 취소"]
{{< /mermaid >}}

출금만 되고 입금이 안 되면 돈이 사라진다. 그래서 두 작업은 반드시 함께 성공하거나 함께 취소되어야 한다.

| 특성 | 뜻 |
|---|---|
| 원자성(Atomicity) | 트랜잭션의 작업은 모두 실행되거나 하나도 실행되지 않아야 한다 |
| 일관성(Consistency) | 트랜잭션 전에 데이터베이스가 올바른 상태였다면, 끝난 뒤에도 올바른 상태여야 한다 |
| 고립성(Isolation) | 실행 중인 트랜잭션의 중간 결과를 다른 트랜잭션이 볼 수 없다 |
| 지속성(Durability) | 트랜잭션이 성공적으로 끝나면 그 결과는 영구히 저장된다 |

COMMIT, ROLLBACK, SAVEPOINT 같은 명령어와 ACID의 자세한 내용은 'TCL' 편에서 다룬다.

## 2. 데이터 모델에서 트랜잭션 읽기

쇼핑몰 주문을 생각해 보자. 주문 한 건은 '주문' 엔터티 한 행과 '주문 상품' 엔터티 여러 행으로 저장된다. 상품이 하나도 없는 주문은 의미가 없고, 주문 없는 주문 상품도 있을 수 없다. 둘은 **반드시 함께** 만들어져야 한다.

{{< mermaid >}}
erDiagram
  ORDERS ||--|{ ORDER_ITEM : "포함한다 / 포함된다"
  ORDERS {
    NUMBER ORDER_NO PK "주문번호"
    DATE ORDER_DATE "주문일자"
  }
  ORDER_ITEM {
    NUMBER ORDER_NO PK "주문번호"
    VARCHAR2 PROD_CODE PK "상품코드"
    NUMBER QTY "수량"
  }
{{< /mermaid >}}

`||--|{` 표기는 양쪽이 모두 필수라는 뜻이다. '각 주문은 하나 이상의 주문 상품을 **항상** 포함하고, 각 주문 상품은 한 주문에 **항상** 포함된다'로 읽는다. 이렇게 양쪽을 필수로 그린 관계는 '두 엔터티의 데이터를 한 트랜잭션으로 묶어 처리하라'는 신호다.

반대로 한쪽이 선택(`o`)이면 따로 처리해도 된다는 뜻이다. 부서와 사원 관계에서 부서 쪽이 선택이면, 사원 없이 부서만 먼저 만들 수 있다.

### SQL로 보는 하나의 트랜잭션

```sql
INSERT INTO ORDERS     (ORDER_NO, ORDER_DATE)      VALUES (100, DATE '2024-10-27');
INSERT INTO ORDER_ITEM (ORDER_NO, PROD_CODE, QTY)  VALUES (100, 'P1', 3);
INSERT INTO ORDER_ITEM (ORDER_NO, PROD_CODE, QTY)  VALUES (100, 'P2', 1);
COMMIT;   -- 세 문장을 한꺼번에 확정
```

중간에 오류가 나면 COMMIT 대신 ROLLBACK을 실행해 주문과 주문 상품을 모두 취소한다. 주문 헤더만 남고 상품이 빠진 '반쪽짜리 주문'이 생기지 않는다.

> **쉬운 설명**
>
> 택배 상자와 송장은 한 몸이다. 송장만 붙이고 물건을 안 넣거나, 물건만 넣고 송장을 안 붙이면 배송이 안 된다. 데이터 모델에서 양쪽을 '항상'으로 그린 관계는 '이 둘은 택배 상자와 송장처럼 함께 처리하라'는 표시다.

## 헷갈렸던 것들

- 함께 생성되어야 하는 두 엔터티는 관계를 양쪽 모두 **필수**로 표현한다.
- 필수 관계로 묶인 데이터는 하나의 트랜잭션에서 함께 COMMIT해야 한다. 따로 COMMIT하면 한쪽만 저장될 수 있다.
- 트랜잭션의 특성은 원자성, 일관성, 고립성, 지속성(ACID)이다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 트랜잭션 | 함께 성공하거나 함께 실패해야 하는 작업의 묶음 |
| 필수 관계 | 상대 엔터티가 반드시 있어야 하는 관계 |
| COMMIT / ROLLBACK | 변경을 확정 / 변경을 취소 |
| ACID | 원자성, 일관성, 고립성, 지속성 |

## 복습 문제

**1.** 주문과 주문 상품처럼 반드시 함께 생성되어야 하는 두 엔터티의 관계를 데이터 모델에서 표현하는 방법은?

① 양쪽 모두 필수 관계로 표현한다 ② 양쪽 모두 선택 관계로 표현한다 ③ 관계를 표현하지 않는다 ④ 상호배타적 관계로 표현한다

**2.** 트랜잭션의 작업은 모두 실행되거나 하나도 실행되지 않아야 한다는 특성은?

① 원자성 ② 일관성 ③ 고립성 ④ 지속성

**3.** 주문 헤더를 입력하고 COMMIT한 뒤, 주문 상품을 입력하다 오류가 나서 ROLLBACK했다. 결과로 옳은 것은?

① 주문 헤더만 남고 주문 상품은 없다 ② 주문 헤더와 주문 상품이 모두 취소된다 ③ 주문 상품만 남는다 ④ 둘 다 저장된다

## 답과 풀이

1. ① 함께 생성되어야 하면 양쪽 필수 관계로 표현한다.
2. ① 원자성이다.
3. ① 이미 COMMIT한 주문 헤더는 ROLLBACK으로 취소되지 않는다. 그래서 두 작업을 한 트랜잭션으로 묶어야 한다.
