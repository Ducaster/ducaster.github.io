속성은 기본·설계·파생 속성의 구분과 도메인의 뜻을 많이 묻는다.

## 요약

- 속성은 업무에서 관리하려는, 의미상 더 이상 나눌 수 없는 최소의 데이터 단위다.
- 한 엔터티는 두 개 이상의 속성을 갖고, 한 속성은 인스턴스마다 하나의 값만 가진다.
- 속성은 특성에 따라 기본, 설계, 파생 속성으로, 엔터티 구성 방식에 따라 PK, FK, 일반 속성으로 나뉜다.
- 도메인은 속성이 가질 수 있는 값의 범위다.

## 1. 속성의 정의

**속성(Attribute)** 은 엔터티가 가진 성격을 나타내는, 의미상 더 이상 쪼갤 수 없는 최소 단위의 데이터다. 테이블의 컬럼에 해당한다.

엔터티, 인스턴스, 속성, 속성값의 관계는 다음과 같다.

| 관계 | 설명 |
|---|---|
| 엔터티 : 인스턴스 | 한 엔터티는 두 개 이상의 인스턴스를 가진다 |
| 엔터티 : 속성 | 한 엔터티는 두 개 이상의 속성을 가진다 |
| 속성 : 속성값 | 한 인스턴스에서 한 속성은 하나의 값만 가진다 |

한 속성에 값이 여러 개 들어가야 한다면(예: 한 사원의 전화번호 여러 개) 그 속성은 별도의 엔터티로 분리해야 한다. 이것이 제1정규화의 출발점이다.

## 2. 속성의 분류

### 속성의 특성에 따른 분류

| 분류 | 설명 | 예 |
|---|---|---|
| 기본 속성(Basic) | 업무 분석으로 바로 도출한, 업무에 원래 있는 속성 | 사원명, 입사일, 제품 가격 |
| 설계 속성(Designed) | 업무에는 없지만 설계하면서 규칙화나 식별을 위해 새로 만든 속성 | 일련번호, 상품 코드, 상태 코드 |
| 파생 속성(Derived) | 다른 속성에서 계산하거나 변형해 만든 속성 | 합계, 평균, 주문 총액 |

파생 속성은 원래 값이 바뀔 때 함께 바꿔 줘야 해서 **데이터 정합성**을 유지하기 어렵다. 그래서 꼭 필요한 경우에만 적게 정의한다.

### 엔터티 구성 방식에 따른 분류

| 분류 | 설명 | 예(EMP 테이블) |
|---|---|---|
| PK(Primary Key) 속성 | 인스턴스를 식별하는 속성 | EMPNO |
| FK(Foreign Key) 속성 | 다른 엔터티와의 관계에서 포함된 속성 | DEPTNO, MGR |
| 일반 속성 | PK, FK가 아닌 나머지 속성 | ENAME, JOB, SAL |

### 그 밖의 분류

| 분류 | 설명 | 예 |
|---|---|---|
| 단순 속성 / 복합 속성 | 더 나눌 수 없음 / 여러 의미로 나눌 수 있음 | 나이 / 주소(시, 구, 동) |
| 단일값 속성 / 다중값 속성 | 값이 하나 / 값이 여러 개(별도 엔터티로 분리 대상) | 주민등록번호 / 전화번호들, 자격증들 |

> **쉬운 설명**
>
> 학생 기록부로 생각하면 쉽다. 이름과 생년월일은 원래 있는 기본 속성, 학교에서 붙여 준 학번은 설계 속성, 국어·영어·수학 점수로 계산한 평균은 파생 속성이다. 평균은 점수가 바뀔 때마다 다시 계산해야 해서, 잊어버리면 기록이 서로 맞지 않게 된다.

## 3. 도메인

**도메인(Domain)** 은 각 속성이 가질 수 있는 값의 범위다. 데이터 타입과 크기, 제약 조건으로 정한다.

| 속성 | 도메인 예 |
|---|---|
| 성별 | '남', '여' |
| 학년 | 1부터 6까지의 정수 |
| 급여 | 0 이상, NUMBER(7) |

도메인을 정해 두면 엉뚱한 값(예: 학년 9)이 들어오는 것을 막을 수 있다. 데이터베이스에서는 데이터 타입과 CHECK 제약 조건으로 구현한다.

## 4. 속성의 명명 규칙

- 해당 업무에서 쓰는 이름을 붙인다.
- 서술식 이름은 쓰지 않는다('고객이 주문한 날짜' X, '주문일자' O).
- 약어는 되도록 쓰지 않는다.
- 전체 데이터 모델에서 유일한 이름을 쓰는 것이 좋다.

## 헷갈렸던 것들

- 한 인스턴스에서 한 속성은 **하나의 값**만 가진다. 값이 여러 개면 별도 엔터티로 분리한다.
- 일련번호, 코드처럼 설계하면서 만든 속성은 **설계 속성**이다.
- 합계, 평균처럼 계산된 속성은 **파생 속성**이고, 정합성 문제 때문에 최소한으로 정의한다.
- 도메인은 속성이 가질 수 있는 값의 범위다.
- 속성 이름은 서술식으로 짓지 않는다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 속성 | 엔터티의 성격을 나타내는 최소 단위 데이터 |
| 기본 / 설계 / 파생 속성 | 업무에서 도출 / 설계 중 생성 / 계산으로 생성 |
| 복합 속성 | 여러 의미로 나눌 수 있는 속성 |
| 다중값 속성 | 값이 여러 개인 속성 |
| 도메인 | 속성이 가질 수 있는 값의 범위 |

## 복습 문제

**1.** 다른 속성으로부터 계산되어 만들어지는 속성은?

① 기본 속성 ② 설계 속성 ③ 복합 속성 ④ 파생 속성

**2.** 속성에 대한 설명으로 옳지 않은 것은?

① 한 엔터티는 두 개 이상의 속성을 가진다 ② 속성은 의미상 더 이상 분리되지 않는 최소 단위다 ③ 한 인스턴스에서 한 속성은 여러 개의 값을 가질 수 있다 ④ 속성 이름은 서술식으로 짓지 않는다

**3.** 속성이 가질 수 있는 값의 범위를 뜻하는 용어는?

① 엔터티 ② 인스턴스 ③ 관계 ④ 도메인

**4.** 업무에는 없지만 상품을 식별하려고 새로 만든 '상품코드'는 어떤 속성인가?

① 기본 속성 ② 파생 속성 ③ 다중값 속성 ④ 설계 속성

## 답과 풀이

1. ④ 계산으로 만든 속성은 파생 속성이다.
2. ③ 한 속성은 하나의 값만 가진다. 값이 여러 개면 엔터티로 분리해야 한다.
3. ④ 도메인이다.
4. ④ 설계하면서 새로 만든 속성은 설계 속성이다.
