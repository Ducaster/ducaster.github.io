1과목 다섯 번째, 식별자. 주식별자의 네 가지 특징, 식별자 분류, 식별 관계와 비식별 관계의 차이는 매회 나온다고 봐도 된다.

## 요약

- 식별자는 엔터티 안에서 인스턴스를 구분하는 속성이다.
- 주식별자는 유일성, 최소성, 불변성, 존재성을 만족해야 한다.
- 식별자는 대표성(주식별자, 보조식별자), 생성 방식(내부, 외부), 속성 수(단일, 복합), 대체 여부(본질, 인조)로 분류한다.
- 부모의 주식별자를 자식의 주식별자로 물려받으면 식별 관계, 일반 속성으로 물려받으면 비식별 관계다.

## 1. 식별자와 주식별자의 특징

**식별자(Identifier)** 는 한 엔터티 안에서 각 인스턴스를 구분해 주는 속성이다. 물리 모델에서는 기본키(PK)가 된다.

| 특징 | 뜻 | 예 |
|---|---|---|
| 유일성 | 주식별자로 엔터티 안의 모든 인스턴스를 유일하게 구분한다 | 사원번호가 같은 사원은 없다 |
| 최소성 | 주식별자를 이루는 속성의 수는 유일성을 만족하는 최소한이어야 한다 | 사원번호만으로 충분하면 사원번호 + 이름으로 하지 않는다 |
| 불변성 | 한번 정한 주식별자 값은 바뀌지 않아야 한다 | 사원번호는 입사부터 퇴사까지 같다 |
| 존재성 | 주식별자 값은 반드시 있어야 한다(NOT NULL) | 사원번호가 없는 사원은 없다 |

## 2. 식별자의 분류

| 분류 기준 | 종류 | 설명 |
|---|---|---|
| 대표성 여부 | 주식별자 | 인스턴스를 대표하는 식별자. 다른 엔터티와 참조 관계를 연결할 수 있다 |
| | 보조식별자 | 인스턴스를 구분할 수는 있지만 대표하지는 못하는 식별자. 참조 관계 연결에 쓰지 않는다(예: 주민등록번호) |
| 스스로 생성 여부 | 내부식별자 | 엔터티 안에서 스스로 만들어진 식별자 |
| | 외부식별자 | 다른 엔터티와의 관계로 받아 온 식별자(FK) |
| 속성의 수 | 단일식별자 | 하나의 속성으로 이루어짐 |
| | 복합식별자 | 둘 이상의 속성으로 이루어짐 |
| 대체 여부 | 본질식별자 | 업무에 의해 만들어진 식별자 |
| | 인조식별자 | 업무와 관계없이 인위적으로 만든 식별자(일련번호 등) |

### 주식별자를 정하는 기준

- 업무에서 자주 쓰이는 속성을 주식별자로 정한다.
- 명칭, 내역처럼 이름으로 기술되는 속성은 피한다(이름은 겹치거나 바뀔 수 있다).
- 복합식별자로 정할 때 속성이 너무 많아지지 않게 한다. 너무 많으면 인조식별자를 검토한다.

## 3. 식별 관계와 비식별 관계

부모 엔터티의 주식별자가 자식 엔터티로 전달될 때, 어디에 들어가느냐에 따라 두 가지로 나뉜다.

| 구분 | 식별 관계(Identifying) | 비식별 관계(Non-Identifying) |
|---|---|---|
| 상속 위치 | 부모의 주식별자가 자식의 주식별자 일부가 된다 | 부모의 주식별자가 자식의 일반 속성이 된다 |
| 표기 | 실선 | 점선 |
| 연결 강도 | 강한 연결. 부모가 있어야 자식이 생긴다 | 약한 연결. 부모 없이도 자식이 생길 수 있다(FK가 NULL 가능) |
| 장점 | 자식 테이블만으로 부모 정보를 알 수 있어 조인이 줄어든다 | 자식의 주식별자가 단순하다 |
| 단점 | 관계가 길게 이어지면 자식의 주식별자 속성이 계속 늘어난다 | 부모 정보를 보려면 조인이 늘어난다 |

Mermaid ERD에서도 식별 관계는 실선(`--`), 비식별 관계는 점선(`..`)으로 그린다. 주문 상품은 주문 없이 존재할 수 없으니 식별 관계, 사원은 부서가 없어도(임사원처럼) 존재할 수 있으니 비식별 관계가 자연스럽다.

### 비식별 관계를 고려할 때

- 자식 엔터티가 부모 없이도 독립적으로 생성될 수 있을 때
- 부모와 자식의 관계가 약할 때(자식이 다른 부모로 옮겨 갈 수 있을 때)
- 식별 관계가 길게 이어져 자식 엔터티의 주식별자 속성이 너무 많아질 때
- 자식 엔터티가 독립적인 주식별자를 가져야 할 때

> **쉬운 설명**
>
> 주식별자는 학교의 학번과 같다. 학번은 겹치지 않고(유일성), 학번 하나면 충분하고(최소성), 졸업할 때까지 바뀌지 않고(불변성), 없는 학생은 없다(존재성). 식별 관계는 '1학년 3반 12번'처럼 반 번호가 학생 번호 안에 들어간 것, 비식별 관계는 학번은 따로 있고 반 번호는 그냥 정보로 적어 둔 것이다.

## 헷갈렸던 것들

- 주식별자의 특징은 유일성, 최소성, 불변성, 존재성이다. '편의성', '가변성'은 틀린 보기다.
- 보조식별자는 인스턴스를 구분할 수 있지만 참조 관계 연결에는 쓰지 않는다.
- 외부식별자는 다른 엔터티에서 받아 온 식별자(FK)이다.
- 식별 관계는 실선, 비식별 관계는 점선이다.
- 식별 관계가 계속 이어지면 자식의 PK 속성 수가 늘어나 SQL이 복잡해진다.
- 비식별 관계에서는 부모 없이 자식이 생길 수 있어 FK가 NULL일 수 있다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 주식별자 | 인스턴스를 대표하는 식별자 |
| 보조식별자 | 구분은 되지만 대표하지 못하는 식별자 |
| 외부식별자 | 관계로 받아 온 식별자 |
| 복합식별자 | 둘 이상의 속성으로 된 식별자 |
| 식별 관계 | 부모 PK가 자식 PK에 포함되는 관계 |
| 비식별 관계 | 부모 PK가 자식의 일반 속성이 되는 관계 |

## 복습 문제

**1.** 주식별자의 특징이 아닌 것은?

① 유일성 ② 최소성 ③ 불변성 ④ 확장성

**2.** 주민등록번호처럼 인스턴스를 구분할 수는 있지만 대표 식별자로 쓰지 않아 참조 관계 연결에 사용하지 않는 식별자는?

① 주식별자 ② 외부식별자 ③ 보조식별자 ④ 인조식별자

**3.** 식별 관계에 대한 설명으로 옳지 않은 것은?

① 부모의 주식별자가 자식의 주식별자에 포함된다 ② 부모 없이도 자식 인스턴스가 생성될 수 있다 ③ 실선으로 표기한다 ④ 관계가 길게 이어지면 자식의 주식별자 속성이 늘어난다

**4.** 비식별 관계를 선택하는 경우로 알맞지 않은 것은?

① 자식 테이블만으로 부모의 식별 정보를 바로 알아야 한다 ② 자식이 부모 없이도 생성될 수 있다 ③ 부모와 자식 사이의 관계가 약하다 ④ 자식의 주식별자 속성이 너무 많아졌다

## 답과 풀이

1. ④ 주식별자의 특징은 유일성, 최소성, 불변성, 존재성이다.
2. ③ 보조식별자다.
3. ② 부모 없이 자식이 생길 수 있는 것은 비식별 관계다.
4. ① 자식만으로 부모의 식별 정보를 알 수 있는 것은 식별 관계의 장점이다.
