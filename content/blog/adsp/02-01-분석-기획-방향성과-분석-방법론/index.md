2과목 '데이터 분석 기획' 첫 정리. 분석 기획 방향성 도출과 분석 방법론 부분이다. 2과목에서 제일 많이 나오는 게 KDD, CRISP-DM, 빅데이터 분석 방법론의 단계 순서라서 이 글에 몰아서 정리했다.

## 요약

- 분석 기획은 분석을 시작하기 전에 무엇을 풀지(과제)와 어떻게 관리할지(방안)를 미리 정하는 일이다.
- 분석 주제는 대상(What)과 방법(How)을 아는지 모르는지에 따라 최적화, 솔루션, 통찰, 발견으로 나뉜다.
- 분석 방법론은 절차, 방법, 도구와 기법, 템플릿과 산출물로 이루어진다.
- KDD는 5단계, CRISP-DM은 6단계, 빅데이터 분석 방법론은 5단계다.
- 빅데이터 분석 방법론은 단계(Phase), 태스크(Task), 스텝(Step)의 3계층으로 구성된다.

## 1. 분석 기획 방향성 도출

### 분석 기획이란

**분석 기획**은 실제 분석을 하기 전에 어떤 과제를 수행할지 정의하고, 의도한 결과를 얻기 위한 관리 방안을 미리 계획하는 일이다. 분석 기획을 잘하려면 세 가지 역량이 균형을 이뤄야 한다.

| 역량 | 내용 |
|---|---|
| 수학·통계학적 지식 | 분석 기법을 이해하고 고른다 |
| 정보기술(IT) | 프로그래밍, 데이터 처리와 관리 |
| 해당 비즈니스에 대한 이해와 전문성 | 무엇이 실제 문제인지 안다 |

### 분석 주제의 네 가지 유형

분석 대상(What)과 분석 방법(How)을 아는지에 따라 접근 방식이 달라진다.

| | 분석 방법을 안다(Known) | 분석 방법을 모른다(Un-Known) |
|---|---|---|
| 분석 대상을 안다(Known) | 최적화(Optimization) | 솔루션(Solution) |
| 분석 대상을 모른다(Un-Known) | 통찰(Insight) | 발견(Discovery) |

- **최적화:** 문제도 알고 푸는 방법도 알 때, 기존 방법을 개선해 더 나은 결과를 낸다.
- **솔루션:** 문제는 알지만 방법을 모를 때, 해법을 찾는다.
- **통찰:** 방법은 있지만 무엇을 풀지 모를 때, 기존 분석으로 새 인사이트를 끌어낸다.
- **발견:** 둘 다 모를 때, 새로운 분석 대상 자체를 찾아낸다.

> **쉬운 설명**
>
> 배달 앱으로 비유하면, '배달 시간을 줄이자'는 문제와 '경로 최적화 알고리즘'이라는 방법을 다 알면 최적화다. 배달 시간을 줄이고 싶은데 방법을 모르면 솔루션, 쌓인 주문 데이터를 늘 하던 방식으로 보다가 새로운 사실을 알게 되면 통찰, 아무 목표 없이 데이터를 보다가 새로운 사업 기회를 찾으면 발견이다.

### 목표 시점별 분석 기획

| 구분 | 당면한 과제 단위 접근 | 마스터 플랜 단위 접근 |
|---|---|---|
| 1차 목표 | Speed & Test | Accuracy & Deploy |
| 과제 유형 | Quick-Win(빠르게 성과를 내는 과제) | Long Term View(장기적 관점) |
| 접근 방식 | Problem Solving(문제 해결) | Problem Definition(문제 정의) |

두 방식을 함께 쓰는 것이 좋다. 마스터 플랜으로 큰 방향을 잡고, 그 안에서 Quick-Win 과제로 빠르게 성과를 보여 주며 분석의 가치를 증명하는 식이다.

### 분석 기획 시 고려사항

| 고려사항 | 내용 |
|---|---|
| 가용 데이터(available data) | 분석에 쓸 데이터가 있는지, 어떤 유형(정형, 반정형, 비정형)인지 먼저 확인한다 |
| 적절한 유즈케이스(proper use-case) | 비슷한 분석 사례나 솔루션이 있다면 최대한 활용한다 |
| 장애요소(low barrier of execution) | 분석 결과를 실제 업무에 적용하기까지의 걸림돌(비용, 조직 문화, 정확도 문제)을 미리 따진다 |

## 2. 분석 방법론

### 방법론이란

**분석 방법론**은 분석을 효과적으로 하기 위한 체계적인 절차다. 방법론이 있으면 분석가의 경험이나 직관에만 기대지 않고 일관된 품질을 낼 수 있다. 방법론은 다음 요소로 이루어진다.

| 구성 요소 | 뜻 |
|---|---|
| 절차(Procedures) | 어떤 순서로 하는가 |
| 방법(Methods) | 각 단계를 어떻게 하는가 |
| 도구와 기법(Tools & Techniques) | 무엇을 써서 하는가 |
| 템플릿과 산출물(Templates & Outputs) | 무엇을 남기는가 |

방법론이 생기는 과정은 개인의 암묵지가 형식화되고(형식지), 이것이 체계화되어 방법론이 되고, 다시 개인에게 내재화되는 순환으로 설명한다. 합리적 의사결정을 방해하는 요소로는 **고정관념(stereotype)**, **편향된 생각(bias)**, **프레이밍 효과(framing effect)** 가 있다. 프레이밍 효과는 같은 내용도 어떻게 표현하느냐에 따라 판단이 달라지는 현상이다.

### 방법론의 적용 모델

| 모델 | 특징 |
|---|---|
| 폭포수 모델(Waterfall) | 단계를 순서대로 진행하고, 앞 단계가 끝나야 다음 단계로 넘어간다. 하향식이며 문제가 생기면 이전 단계로 돌아가는 피드백이 있다 |
| 프로토타입 모델(Prototype) | 일부를 먼저 만들어 사용자에게 보여 주고 결과를 보며 개선한다. 상향식이며 사용자 요구가 불명확할 때 유리하다 |
| 나선형 모델(Spiral) | 반복할 때마다 위험을 분석하며 점진적으로 개발한다. 처음 시도하는 프로젝트에 적합하지만 관리가 복잡하다 |

### 방법론의 3계층 구조

| 계층 | 설명 | 산출물 |
|---|---|---|
| 단계(Phase) | 프로세스 그룹. 단계가 끝날 때마다 기준선(baseline)을 정해 관리한다 | 단계별 산출물 |
| 태스크(Task) | 단계를 구성하는 단위 활동. 물리적이거나 논리적인 단위로 품질 검토의 항목이 된다 | 태스크별 보고서 |
| 스텝(Step) | WBS(작업 분할 구조)의 워크 패키지에 해당하며, 입력자료·처리 및 도구·출력자료로 구성된 단위 프로세스 | 스텝별 산출물 |

### KDD 분석 방법론

**KDD(Knowledge Discovery in Databases)** 는 1996년 패야드(Fayyad)가 정리한, 데이터에서 패턴을 찾는 데이터 마이닝 프로세스다.

{{< mermaid >}}
flowchart LR
  A["데이터셋 선택<br>Selection"] --> B["데이터 전처리<br>Preprocessing"]
  B --> C["데이터 변환<br>Transformation"]
  C --> D["데이터 마이닝<br>Data Mining"]
  D --> E["해석과 평가<br>Interpretation / Evaluation"]
{{< /mermaid >}}

| 단계 | 하는 일 |
|---|---|
| 데이터셋 선택 | 비즈니스 도메인을 이해하고 목표를 정한 뒤, 데이터베이스나 원시 데이터에서 분석 대상 데이터를 고른다 |
| 데이터 전처리 | 잡음(noise), 이상치(outlier), 결측치(missing value)를 찾아 제거하거나 처리한다 |
| 데이터 변환 | 분석 목적에 맞게 변수를 고르고 차원을 줄이며, 학습용과 검증용 데이터로 나눈다 |
| 데이터 마이닝 | 분석 목적에 맞는 기법과 알고리즘을 골라 패턴을 찾는다 |
| 해석과 평가 | 결과를 해석하고 평가해 업무에 활용한다 |

### CRISP-DM 분석 방법론

**CRISP-DM(Cross Industry Standard Process for Data Mining)** 은 1996년 유럽연합의 ESPRIT 프로젝트에서 시작해 1999년 첫 버전이 나온 방법론이다. 단계, 일반화 태스크, 세분화 태스크, 프로세스 실행의 **4레벨** 구조이고, **6단계**로 진행된다. 단계 사이를 오가는 피드백이 있다는 점이 특징이다.

{{< mermaid >}}
flowchart TB
  BU["업무 이해"] <--> DU["데이터 이해"]
  DU --> DP["데이터 준비"]
  DP <--> M["모델링"]
  M --> E["평가"]
  E --> D["전개"]
  E -.-> BU
{{< /mermaid >}}

| 단계 | 주요 태스크 |
|---|---|
| 업무 이해(Business Understanding) | 업무 목적 파악, 상황 파악, 데이터 마이닝 목표 설정, 프로젝트 계획 수립 |
| 데이터 이해(Data Understanding) | 초기 데이터 수집, 데이터 기술 분석, 데이터 탐색, 데이터 품질 확인 |
| 데이터 준비(Data Preparation) | 분석용 데이터셋 선택, 데이터 정제, 분석용 데이터셋 편성, 데이터 통합, 데이터 포맷팅 |
| 모델링(Modeling) | 모델링 기법 선택, 모델 테스트 계획 설계, 모델 작성, 모델 평가 |
| 평가(Evaluation) | 분석 결과 평가, 모델링 과정 평가, 모델 적용성 평가 |
| 전개(Deployment) | 전개 계획 수립, 모니터링과 유지보수 계획 수립, 프로젝트 종료 보고서 작성, 프로젝트 리뷰 |

### KDD와 CRISP-DM 비교

| KDD | CRISP-DM |
|---|---|
| 분석 대상 비즈니스 이해 | 업무 이해 |
| 데이터셋 선택, 데이터 전처리 | 데이터 이해 |
| 데이터 변환 | 데이터 준비 |
| 데이터 마이닝 | 모델링 |
| 해석과 평가 | 평가 |
| 데이터 마이닝 활용 | 전개 |

> **쉬운 설명**
>
> 두 방법론 모두 요리 과정과 같다. 장보기(데이터 선택), 손질(전처리), 썰기와 양념(변환), 조리(마이닝), 맛보기(평가) 순서다. CRISP-DM은 여기에 '손님이 뭘 원하나'를 먼저 묻는 업무 이해와, 완성된 요리를 손님상에 내는 전개까지 포함하고, 맛이 이상하면 앞 단계로 돌아가는 것을 공식적으로 허용한다.

### 빅데이터 분석 방법론

빅데이터 분석 방법론은 단계(Phase), 태스크(Task), 스텝(Step)의 3계층, 5단계로 구성된다.

{{< mermaid >}}
flowchart TB
  P["분석 기획<br>Planning"] --> R["데이터 준비<br>Preparing"]
  R --> A["데이터 분석<br>Analyzing"]
  A -.->|"데이터가 부족하면"| R
  A --> D["시스템 구현<br>Developing"]
  D --> E["평가 및 전개<br>Deploying"]
{{< /mermaid >}}

| 단계 | 태스크 | 주요 스텝과 산출물 |
|---|---|---|
| 분석 기획 | 비즈니스 이해 및 범위 설정 | 비즈니스 이해, 프로젝트 범위 설정 → SOW(Statement Of Work, 범위 정의서) |
| | 프로젝트 정의 및 계획 수립 | 데이터 분석 프로젝트 정의, 수행 계획 수립 → WBS(Work Breakdown Structure) |
| | 프로젝트 위험계획 수립 | 위험 식별, 위험 대응 계획 수립(회피, 전이, 완화, 수용) |
| 데이터 준비 | 필요 데이터 정의 | 데이터 정의, 데이터 획득 방안 수립 |
| | 데이터 스토어 설계 | 정형 데이터 스토어 설계, 비정형 데이터 스토어 설계 |
| | 데이터 수집 및 정합성 점검 | 데이터 수집 및 저장, 데이터 정합성 점검 |
| 데이터 분석 | 분석용 데이터 준비 | 비즈니스 룰 확인, 분석용 데이터셋 준비 |
| | 텍스트 분석 | 텍스트 데이터 확인 및 추출, 텍스트 데이터 분석 |
| | 탐색적 분석 | 탐색적 데이터 분석(EDA), 데이터 시각화 |
| | 모델링 | 데이터 분할, 데이터 모델링, 모델 적용 및 운영 방안 |
| | 모델 평가 및 검증 | 모델 평가, 모델 검증 |
| 시스템 구현 | 설계 및 구현 | 시스템 분석 및 설계, 시스템 구현 |
| | 시스템 테스트 및 운영 | 시스템 테스트, 시스템 운영 계획 |
| 평가 및 전개 | 모델 발전 계획 수립 | 모델 발전 계획 |
| | 프로젝트 평가 및 보고 | 프로젝트 성과 평가, 프로젝트 종료 |

위험 대응 방법 네 가지도 자주 나온다.

| 대응 | 뜻 | 예 |
|---|---|---|
| 회피(Avoid) | 위험이 생길 일을 하지 않는다 | 품질이 불확실한 외부 데이터를 쓰지 않는다 |
| 전이(Transfer) | 위험을 다른 쪽에 넘긴다 | 보험에 들거나 외부 업체와 계약으로 책임을 나눈다 |
| 완화(Mitigate) | 위험의 영향이나 확률을 줄인다 | 데이터 수집 일정을 넉넉히 잡는다 |
| 수용(Accept) | 위험을 받아들이고 대비만 한다 | 예비비를 마련해 둔다 |

## 헷갈렸던 것들

- 대상은 알고 방법을 모르면 **솔루션**, 대상은 모르고 방법을 알면 **통찰**이다. 두 칸을 바꿔 묻는 문제가 많다.
- Quick-Win은 당면 과제 접근의 특징이고, Accuracy & Deploy는 마스터 플랜 접근의 특징이다.
- 폭포수 모델은 하향식, 프로토타입 모델은 상향식이다.
- KDD는 5단계, CRISP-DM은 6단계다. CRISP-DM에서 피드백이 있는 곳은 '업무 이해 ↔ 데이터 이해', '데이터 준비 ↔ 모델링'이다.
- SOW는 분석 기획 단계의 '프로젝트 범위 설정', WBS는 '프로젝트 정의 및 계획 수립'의 산출물이다.
- 빅데이터 분석 방법론에서 데이터 분석 단계 중 데이터가 부족하면 **데이터 준비** 단계로 돌아간다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| Quick-Win | 짧은 시간에 눈에 보이는 성과를 내는 과제 |
| 프레이밍 효과 | 같은 내용도 표현 방식에 따라 판단이 달라지는 현상 |
| KDD | 데이터셋 선택 → 전처리 → 변환 → 마이닝 → 해석과 평가 |
| CRISP-DM | 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개 |
| SOW | 프로젝트 범위 정의서 |
| WBS | 프로젝트 작업을 잘게 나눈 작업 분할 구조 |

## 복습 문제

**1.** 분석 대상은 알지만 분석 방법을 모르는 경우의 분석 주제 유형은?

① 최적화 ② 솔루션 ③ 통찰 ④ 발견

**2.** KDD 분석 방법론의 단계 순서로 옳은 것은?

① 선택 → 전처리 → 변환 → 마이닝 → 평가 ② 선택 → 변환 → 전처리 → 마이닝 → 평가 ③ 전처리 → 선택 → 변환 → 마이닝 → 평가 ④ 선택 → 전처리 → 마이닝 → 변환 → 평가

**3.** CRISP-DM의 '데이터 준비' 단계에 해당하는 태스크가 아닌 것은?

① 데이터 정제 ② 데이터 품질 확인 ③ 데이터 통합 ④ 데이터 포맷팅

**4.** 빅데이터 분석 방법론에서 프로젝트 범위 정의서(SOW)를 작성하는 단계는?

① 분석 기획 ② 데이터 준비 ③ 데이터 분석 ④ 평가 및 전개

**5.** 사용자 요구사항이 불명확할 때 일부를 먼저 만들어 보여 주며 개선하는 방법론 모델은?

① 폭포수 모델 ② 나선형 모델 ③ 프로토타입 모델 ④ CRISP-DM

## 답과 풀이

1. ② 대상을 알고 방법을 모르면 솔루션을 찾는 유형이다.
2. ① 데이터셋 선택 → 전처리 → 변환 → 데이터 마이닝 → 해석과 평가 순서다.
3. ② 데이터 품질 확인은 '데이터 이해' 단계의 태스크다.
4. ① SOW는 분석 기획 단계의 '비즈니스 이해 및 범위 설정' 태스크에서 작성한다.
5. ③ 프로토타입 모델은 결과물을 먼저 보여 주고 개선하는 상향식 모델이다.
